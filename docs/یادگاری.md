# یادگاری: همه‌ی دال در یک نگاه

این فایل برای روزی است که همه‌ی سرورها و ابزارهای ساخت خاموش شده‌اند و فقط این مخزن مانده است. با همین مخزن می‌توانید همه‌چیز را از صفر بالا بیاورید.

## چه چیزهایی دارید

| چیز | مسیر | توضیح |
|---|---|---|
| کل سایت و سرور در یک فایل | `release/dal.js` | فقط Node.js نسخه‌ی ۲۲٫۱۳ یا بالاتر می‌خواهد. هیچ نصب دیگری ندارد. |
| اپ اندروید آماده | `release/dal.apk` | فایل نصبی. حدود ۱۷۰ کیلوبایت. |
| کد سایت و سرور | `public/` و `server/` | همه‌ی کدهای اصلی؛ ۳۲ آزمون خودکار در `server/tests/`. |
| کد اپ اندروید | `android/` | پروژه‌ی Gradle بدون کتابخانه‌ی بیرونی. |
| ساخت خودکار اپ | `.github/workflows/android.yml` | روی گیت‌هاب رایگان APK می‌سازد و روی شبیه‌ساز آزمایش می‌کند. |
| راه‌اندازی سرور | `deploy/` | نصب، HTTPS، به‌روزرسانی، پشتیبان، فایل تنظیمات نمونه. |
| راهنماها | `docs/` | همین پوشه. |
| تصویرهای اپ روی شبیه‌ساز | `docs/android-ci/` | نشان می‌دهد اپ واقعاً اجرا شده است. |

## از صفر تا سایت زنده (کوتاه)

1. یک سرور لینوکسی و یک دامنه بگیرید. رکورد A دامنه را به IP سرور بدهید.
2. فایل‌ها را بفرستید و نصب کنید:

```
scp release/dal.js release/dal.apk deploy/*.sh deploy/env.example root@YOUR_SERVER_IP:/root/
ssh root@YOUR_SERVER_IP
sudo bash install.sh ./dal.js
sudo bash https.sh dal.example.ir
```

3. آدرس `https://دامنه/#/setup` را باز کنید و حساب مدیر را بسازید.
4. از «پنل مدیریت ← تنظیمات» ربات بله را وصل کنید (برای یادآور و گزارش هفتگی).
5. پشتیبان شبانه را روشن کنید:

```
sudo cp backup.sh /root/backup.sh
echo '0 3 * * * root bash /root/backup.sh' | sudo tee /etc/cron.d/dal-backup
```

## از صفر تا اپ اندروید

نصب مستقیم: فایل `release/dal.apk` را روی گوشی بزنید.

ساخت با آدرس سایت خودتان: مخزن را در گیت‌هاب نگه دارید، برگه‌ی Actions ← Build Android APK ← Run workflow، و آدرس سایت را بدهید. اگر گیت‌هاب در دسترس نبود، راه ساخت روی کامپیوتر در `docs/اپ-اندروید.md` است.

## به‌روزرسانی و پشتیبان

```
sudo bash update.sh ./dal.js ./dal.apk
sudo bash backup.sh
```

برگرداندن پشتیبان: سرویس را خاموش کنید، فایل فشرده را در `/opt/dal` باز کنید و دوباره روشن کنید. دستور دقیقش بالای فایل `backup.sh` نوشته شده است.

## چه چیزهایی از بیرون لازم است

- سرور و دامنه؛ دال هیچ سرویس ابری ندارد.
- ربات بله یا تلگرام فقط برای هشدار، یادآور و گزارش هفتگی لازم است. بدون آن، همه‌ی بخش‌های دیگر کار می‌کنند.
- نقشه از خود سرور شما کاشی می‌گیرد؛ سرور برای این کار باید به سرویس نقشه دسترسی داشته باشد (داخل ایران ممکن است کند باشد).
- هیچ پیامکی در کار نیست: ورود با موبایل و رمز است و بازیابی با مدیر یا کد بازیابی.

## چه چیزهایی آزمایش شده و چه چیزهایی نه

آزمایش شده با ابزار خودکار:
- ۳۲ آزمون سرور، روی پایگاه‌داده‌ی خالی.
- اپ اندروید روی شبیه‌ساز اندروید ۱۴: نصب، وارد کردن آدرس، بارگذاری سایت، لینک مستقیم به صفحه، اعلان گوشی، صفحه‌ی خطا و دکمه‌ی تلاش دوباره، ذخیره‌ی فایل از سایت داخل اپ.

آزمایش نشده و باید یک بار روی دستگاه و سرور واقعی دیده شود:
- ارسال واقعی بله/تلگرام، اشتراک تقویم روی گوشی واقعی.
- انتخاب عکس از گالری و موقعیت مکانی در اپ.
- قفل برنامه (شبیه‌ساز قفل صفحه ندارد).
- اسکریپت‌های `https.sh`، `update.sh`، `backup.sh` روی سرور واقعی.
- رفتار اعلان‌ها روی گوشی‌هایی که صرفه‌جویی باتری شدید دارند.
